# Cloud Concepts Reflection

## Cloud Services I Use

I rely on cloud-based tools more than I usually notice until I stop and count them. Three that show up in my daily routine are **Messenger**, **Canva**, and **Google Drive**.

## Identifying the Models

**Messenger** falls under **SaaS**, since I only open the app and chat — Meta handles every server and every bit of backend logic without me touching any infrastructure. Its deployment is **Public Cloud**, because the platform runs on shared infrastructure open to anyone who creates an account, with no dedicated environment set aside for individual users.

**Canva** is also **SaaS**, since I log in and design directly inside a browser tab, with no installation or server management on my end. I'd classify its deployment as **Public Cloud** too, since it's built for mass, self-service access, with millions of users drawing from the same shared pool of servers and storage.

**Google Drive** is another clear **SaaS** example: I upload, edit, and share files through a finished interface rather than configuring any storage system myself. It runs on **Public Cloud** infrastructure, since Google owns and operates the underlying servers and makes them available to any user or organization that signs up for an account.

## Git & GitHub for Cloud Projects

Cloud infrastructure today is rarely built by clicking buttons — it's defined through code, scripts, and configuration files, which means a small typo can take down a server as easily as a major design flaw. Version control matters because it gives every change a paper trail: nothing is lost, nothing is guessed at, and any broken change can be rolled back to a known-good state within seconds.

GitHub extends this for teams. Instead of members emailing files back and forth or overwriting each other's work, GitHub lets people branch off, experiment, and merge changes only after review through pull requests. This catches mistakes before they reach live cloud systems, while commit history keeps a running log of who changed what and why, turning cloud management into a transparent, accountable process.
